How it works

Built for the way real migrations start: the database is production, access is guarded, and the first question is not how but how much.

01 — EXTRACT

One script, client-side

Your DBA runs a single read-only SQL*Plus script and hands back a folder of spool files. Nothing else leaves the building; pgrecon never connects to Oracle.

02 — ASSESS

Parser-grade findings

The dump becomes a local SQLite inventory. An ANTLR PL/SQL grammar and 63+ compatibility rules turn it into findings with remedies, plus a defensible effort estimate in person-days.

03 — CONVERT

Prove it or name it

Schema structure converts to PostgreSQL DDL offline: tables, keys, indexes, views, triggers, routines. Everything unproven becomes a named line in a residue report.

Never a silent guess

The design law: never emit DDL PostgreSQL would reject, and never drop an object without saying so. What the converter declines, it names — one object, one reason.

view CO.PRODUCT_REVIEWS: uses JSON_TABLE, which PostgreSQL adds in version 17 with different clause syntax; rewrite the view by hand trigger RECON_TEST.TRG_EMP_AUDIT: runs an autonomous transaction; redesign with dblink or a queue (line 5) trigger RECON_TEST.TRG_EMP_SAL_GUARD: compound triggers combine timing points; restructure as separate triggers by hand mat. view RECON_TEST.MV_DEPT_SALARIES: materialized view emitted as a plain table; the defining query is not in the inventory - recreate it as CREATE MATERIALIZED VIEW and schedule REFRESH by hand (Oracle refresh method: COMPLETE)

A migration stalls on surprises, not on work. The residue report is the complete list of surprises, priced and named, before anyone touches production.

The benchmark

Nine schemas — Oracle's official HR, OE, and CO samples, plus utPLSQL, PLJSON, Logger, Alexandria, and two lab schemas — converted by each tool, then applied statement by statement to a live PostgreSQL 16. Errors are statements PostgreSQL rejected. August 2026.

The claim, precisely: across these nine schemas the converter emitted zero statements PostgreSQL rejected — and everything it cannot prove is a named line in the residue report. It does not mean everything converts: 51 percent of all objects converted mechanically, above 90 percent on the business-shaped schemas, and the gap is dominated by object types and packages, which nothing converts mechanically. One hierarchical view was additionally verified row-for-row against a live Oracle database running the original.
